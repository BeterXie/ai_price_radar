# v3.9.29

中转站每小时运行一轮糖果测试与缓存基准。原先只有 8～12 个输入 Token 的 `Reply OK` 探测无法检验常见模型的提示缓存；新基准连续发送相同的固定长输入，包含不带答案的背景档案和 Sub2API 糖果题。

- 第一请求测可用性、延迟和糖果题。最终整数 21 为通过，其他整数为未通过；超时、截断、空回答和无法识别的答案单列为无法判定。不用第二次答案改写第一次结果，不重试至通过。
- 第二请求仅测缓存，保留相同输入与参数，绝不附上第一次答案。OpenAI 兼容接口附稳定 `prompt_cache_key`，Anthropic 附 ephemeral 缓存标记；路由与缓存是否生效由上游决定。
- 24 小时重复输入缓存率 = 有效第二请求的缓存读取 Token 总和 / 输入 Token 总和。明确返回零才是零，缺失用量、报告输入少于 1,024 Token、失败请求均不计入；缓存写入不算读取。模型可能要求更高的缓存门槛，代理可能增加系统输入或切换账号，因此该数字仅描述这套固定测试，不代表所有业务的缓存表现。
- `/v1/usage` 补充用量仍要求请求计数恰好增加 1、所有 Token 差额与响应输入总数一致；不能归因时保留未知。
- 页面显示糖果通过数/可判定次数、无法判定次数和缓存用量完整次数/重复请求次数。糖果题不认证模型身份或整体能力。旧样本保留用于可用性历史，不混入新缓存与首 Token 聚合。

每轮最多两次模型请求，单次输出上限 4,096 Token、请求等待上限 60 秒、完整调用上限 90 秒。固定前缀避免无限增长的会话历史，实际 Token 与缓存读取量以接口报告为准。

发布前按 `docs/QUICK_DEPLOY.md` 完成门禁。执行 `scripts/migrate_relay_benchmark_v25.py` 前必须在临时 PostgreSQL 16 连续演练两次；在切换 API 前完成迁移。此版本只重建 API、Web 和 importer，数据库结构变更需完成一次完整目录发布。新增可空字段使旧镜像可回滚；不回滚数据库、不删除旧记录。
