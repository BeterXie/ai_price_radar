# QQ AI 价格助手

QQ 私聊、群内机器人查询以及网页 QQ 指令测试入口，可使用 AI 理解自然语言查价、比较商品和解释交付方式。价格、库存、店铺、交付形态、期限和质保来自已经发布的本地快照。

## 使用示例

```text
帮我找一百元以内的 Plus 账号，半成品也可以
我有自己的账号，只想充一个月
只看有质保的
比较第一家和第二家
比较 Plus 月卡的账号与代充
成品、半成品和代充有什么区别？
质保一个月就是能用一个月吗？
```

“账号”含成品和半成品；明确只要成品时才排除半成品。账号不自动等于独享。解释区分会员期限、售后质保、账号号龄和优惠资格；无法确定的属性不补造。

比较指定商品时，分别查询各方案符合条件的优先报价，沿用目录现货优先、可比报价优先和同币种价格排序规则。只有套餐、币种、期限一致且都是可信可比现货时，才说明所选商品哪项价格更低；交付与质保分别展示，不保证商家信誉、封号率或使用稳定性。比较列表序号时使用用户上次看到的列表，快照更新后先刷新，要求用户重新选择。

## 配置

进入 `/admin?tab=settings`，验证管理密钥后，在「QQ 机器人与价格变动通知开关 → AI 价格助手」中填写接口地址、模型、接口格式和 API 密钥。

1. 填写服务商的 API 基础地址，例如 `https://api.openai.com/v1`，不包含 `/chat/completions` 或 `/responses`；生产使用 HTTPS。
2. 填写服务商实际提供且支持函数调用的模型名，没有隐式默认模型。
3. 选择接口格式。Chat Completions 兼容接口须支持 `tools`、强制 `tool_choice`、`parallel_tool_calls`、`max_completion_tokens` 和 `store=false`。Responses 模式使用 `/responses`；GPT-6 系列工具调用应使用此模式。以模型/服务商的实际支持为准。
4. 点击「测试连接」验证当前填写内容，测试会发送一次账号/代充解释请求，不保存配置、不发送 QQ 消息。
5. 勾选「启用 AI 价格助手」并「保存并应用」。下一次模型查询读取新配置，无需重启或重新发布。正在进行的请求仍使用其开始时的配置。

只更换模型时，密钥留空即可保留。更换接口地址必须同时填写对应密钥，防止旧密钥被发送给另一个服务商。关闭 AI 后可以勾选「清除已保存密钥」。关闭 AI 使用原有规则查价；接口超时、限流或模型计划不合法时也会回退。机器人总开关控制 QQ 服务，AI 开关不会自动开启机器人总开关。

配置保存在现有 `system_settings` 表的 `qq_price_ai` 记录中，整体提交后生效，不需要新增表。密钥复用 `BOT_SECRET_ENCRYPTION_KEY` 的凭据加密机制，服务器必须配置有效加密材料；管理接口只返回是否已配置密钥，密钥不回显、不写入浏览器持久存储，不进入公开接口。页面关闭后未保存的输入丢弃。

管理接口均要求 `X-Admin-Key`：`GET /api/v1/admin/bot-ai` 读取、`PUT /api/v1/admin/bot-ai` 保存完整配置、`POST /api/v1/admin/bot-ai/test` 测试草稿。测试成功不代表已保存或已开启。

官方接口参考：[Function calling](https://developers.openai.com/api/docs/guides/function-calling)。

## 工作方式

1. 绑定、通知偏好、关注清单、帮助和行情继续走已有命令；绑定码不交给模型。
2. 精确套餐名、分页、重置、数字序号等直接走现有搜索。
3. 其余 QQ 查询向配置的模型发出一次函数调用请求，提供可见套餐名称、当前问句、上次筛选条件和当前显示报价的结构化字段。
4. 模型只能选择查价、比较、详情、解释、翻页、清筛选、重置或澄清。Pydantic 校验字段、套餐、品牌、金额范围和序号，不执行模型提供的 SQL、URL 或代码。
5. 程序查询本地快照并生成报价；解释使用明确的交付定义，模型自由文本不会直接显示成价格或商家承诺。没有第二次生成价格的模型调用。

复用已有 `httpx`、Pydantic 和快照索引，不新增 SDK、向量数据库或聊天表。每次模型查询短暂读取后台配置，读取后即关闭该数据库会话；模型请求期间不占用全局搜索锁，报价检索仍使用本地快照。QQ 网关接收循环与回复队列分开，模型请求不阻塞心跳 ACK；每个机器人按消息顺序处理，队列有界。

## 数据与限制

- 请求不附加 QQ 用户/群/机器人标识、绑定资料、通知偏好或密钥。用户在问句中自己填写的信息会随问句发送，因此帮助菜单和隐私政策提醒不要提交账号密码、验证码或支付资料。
- 不记录模型请求正文、响应正文或密钥；不保存完整聊天记录。搜索上下文沿用按机器人、群/私聊和发送人隔离的 30 分钟内存会话，重启后清空。
- 每个会话每分钟最多六次模型请求，进程内最多四个模型请求并发。单次网络操作超时 18 秒，连接超时 5 秒；模型响应最大 128 KB，不自动重试产生额外调用。
- 该助手只查询公开目录，不代购、不改分类、不自动修改关注或通知设置，也不进行开放式日常聊天。无法表达的条件会澄清；模型不可用时按规则搜索。
- 搜索会话和限流保存在进程内，多进程部署应保持同一会话落到同一进程。AI 配置每次从数据库读取，后台切换对其他进程的下一次查询也生效。

## 验证

在 `apps\api` 下运行：

```powershell
python -m pytest tests\test_bot_ai_settings.py tests\test_price_assistant.py tests\test_snapshot_chat.py tests\test_auth_and_bot.py tests\test_qq_gateway_privacy.py -q
if ($LASTEXITCODE -ne 0) { throw 'QQ AI price assistant checks failed.' }
```

测试使用本地公开快照样例和模拟模型接口，不发送 QQ 消息。覆盖两种 API 格式、报价一致性、模型错误输出、未知套餐、预算、账号包含半成品、比较、会话隔离、快照更新、限流、敏感命令绕过及网关队列。

真实服务启用前需由管理员在后台填写 API 地址、模型和密钥，使用「测试连接」验证函数调用兼容性。首次上线代码遵循 `docs/QUICK_DEPLOY.md`，之后修改 AI 配置不需要重新部署。
