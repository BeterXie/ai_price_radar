# v3.9.26 中转站缓存采集兼容

AllTokens 的 OpenAI 兼容对话接口返回了输入 Token，但省略缓存明细；同一检测密钥的 `/v1/usage` 能返回明确的缓存读取计数。本版兼容这种 Sub2API 返回方式，沿用原有探活样本和近 24 小时加权统计，不需要数据库迁移。

## 实现

- 每次 OpenAI 兼容探活前读取同一配置地址、同一密钥的累计请求数和三类输入计数；响应自带缓存明细时直接使用响应。
- 成功响应缺少缓存计数时，核对请求后的用量增量。只有请求数恰好增加 1、计数没有倒退、普通输入加缓存读取及缓存创建的增量等于本次响应输入数时，才补入这次探活的缓存计数。
- 记账尚未更新时最多等待 250ms 再读一次；不支持、超时、字段不完整、并发请求或计数不匹配保持未知。用量请求每次限制 5 秒、128 KiB，不影响探活健康状态、对话延迟或首 Token 耗时。
- 只保留核对后的单次输入及缓存 Token，不存余额、费用、用户资料、原始响应或密钥。接口沿用既有公共 HTTPS、DNS 固定、禁止重定向的客户端；不向其他域名发送凭据。

## 核验

- 用候选采集模块在生产容器的独立进程中进行一次真实 AllTokens 短请求，未修改运行中源码或数据库。HTTP 200，响应输入 12 Token、响应缓存字段缺失；用量请求数增加 1，核对缓存读取增量为 0。证明可以采到有效零值，不把字段缺失直接当零。
- API 完整测试：807 passed、4 skipped。覆盖 SSE/JSON、连续三轮稀疏用量、直接缓存字段优先、异步记账、并发调用、计数倒退、缺失/非法字段、累计计数超过 32 位、计费输入归一化、超时及补充请求不污染耗时。
- Web `npm ci`、类型检查和生产构建通过，生产客户端静态文件不含 localhost API 地址。
