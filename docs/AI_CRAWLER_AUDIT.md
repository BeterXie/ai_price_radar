# AI 爬虫可读性审计（2026-08-29）

## 审计边界

本清单来自仓库中的 Next.js 路由、服务端组件和结构化数据实现，并用 Edge 对线上首页做了只读 HTML 抽查。它不是 Google 内部爬虫报告，也不能证明 Google/Bing 已经收录或会生成 AI 摘要。

## 已确认的问题与处理

| 信号 | 爬虫可能读不懂的地方 | 处理结果 |
| --- | --- | --- |
| 实体关系 | 首页线上 HTML 没有 JSON-LD，站点组织者、网站和产品之间没有统一 `@id` 关系。 | 根布局增加 `Organization`、`WebSite`、`SearchAction`；产品和来源页引用网站实体。 |
| 产品语义 | 产品页原来只有价格和可信报价存在时才输出 `Product`，无价产品缺少稳定产品实体。 | 所有产品详情页输出 `Product`；只有有可统计价格时才输出 `AggregateOffer`。 |
| 产品描述 | API 描述与产品分类的边界说明没有稳定出现在 H1 下方。 | H1 下的说明改用产品专属语义介绍，保留原有版式和筛选交互。 |
| 外部依据 | 22 个产品没有统一的三条可验证外部依据链。 | 每个产品从指南来源、官方价格参考和品牌官方来源中去重取三条，并同步到可见折叠依据区和 `citation`。 |
| 内链上下文 | 报价分组折叠前，代表店铺和来源平台不是链接；依赖客户端展开会削弱服务端爬取路径。 | 折叠摘要直接链接代表店铺和来源平台，保留原有展开行为。 |
| 标题层级 | 产品 FAQ 在购买前检查下使用同级 H2；来源、店铺目录的部分数据区没有标题；来源产品报价区直接落到报价行标题。 | FAQ 改为 H3；无标题数据区补语义 H2；没有必要强行增加 H5/H6。 |
| 重复 URL | 指南搜索、店铺筛选/分页、来源分页页可继承主页面索引信号。 | 带查询参数的这些目录页改为 `noindex,follow`，canonical 仍指向无参数入口。 |
| 收录通知 | 仓库没有 IndexNow/Bing Webmaster 的可重复提交入口。 | 增加 PowerShell 7 脚本、IndexNow key route 和运行说明；不伪造站长凭据。 |
| AI 引荐 | 仓库没有 GA4 配置，也没有 AI referrer 事件维度。 | 增加可选 GA4 客户端组件，记录页面路径和首次入口的 `ai_referral` 参数；默认无测量 ID 时不加载。 |

## 已存在、不是问题的部分

- `robots.ts` 已允许公开页面并声明站点地图。
- 产品页、指南页和来源页已经使用服务端渲染，核心文本不是依赖 `useEffect` 才出现。
- `/products` 的查询参数页原本已经有 `noindex` 逻辑；本轮把同一原则扩展到其他目录入口。
- 动态站点地图已经按实际报价生成来源、店铺和产品 URL，本轮没有放开空内容页面。

## 仍需上线后验证的事实

- IndexNow 返回“已接受”只代表通知被接口接收，不代表两小时内抓取或收录。
- Bing Webmaster 需要已验证的站点属性；GA4 需要在后台注册 `ai_referral_source`、`ai_referral_term` 自定义维度。
- AI 平台可能隐藏或改写 referrer；不能仅凭 GA4 referrer 统计所有 AI 访问。
